# معمارية تطبيق التحكم عن بُعد (Remote Desktop)

> نسخة مبدئية للمراجعة — **ليست جاهزة للإنتاج قبل مراجعة أمنية مستقلة.**
> هذا التصميم لأداة تحكم عن بُعد **شفّافة قائمة على الموافقة** بين جهازين يملكهما المستخدم نفسه،
> على غرار الوضع غير المراقَب (unattended) في TeamViewer / AnyDesk / Chrome Remote Desktop.

## 1. المبادئ الحاكمة

1. **الموافقة الصريحة أولاً**: لا وصول دون إقران أوّلي يؤكَّد فيزيائياً على الجهاز المتحكَّم به (Host).
2. **الشفافية**: يبقى على الجهاز المتحكَّم به **مؤشّر جلسة مرئي** طوال الاتصال. لا يوجد وضع خفي أو تعطيل للمؤشر.
3. **أقل صلاحية ممكنة**: التطبيق يعمل ضمن صلاحيات ويندوز الممنوحة له فقط؛ لا حقن شيفرة، لا rootkits، لا تجاوز UAC.
4. **تشفير قياسي فقط**: نعتمد على تشفير البروتوكولات المعروفة (DTLS-SRTP في WebRTC، TLS 1.3 في الإشارات) ولا نخترع خوارزميات.
5. **ربط التفويض بالجهاز**: معرفة معرّف الجهاز وحده لا يكفي؛ يلزم مفتاح خاص مخزَّن بأمان على الجهاز المتحكِّم (Controller).

## 2. المكوّنات عالية المستوى

```
┌────────────────────────┐         Signaling (WSS/TLS 1.3)        ┌────────────────────────┐
│   Controller (الكمبيوتر  │◄──────────────────────────────────────►│  Signaling Service      │
│   الأول — المتحكِّم)      │                                        │  (ASP.NET Core)         │
│                        │                                        │  - مصادقة الأجهزة         │
│  - WPF UI (إعداد/إقران) │                                        │  - تبادل SDP/ICE         │
│  - عميل WebRTC          │         WebRTC (DTLS-SRTP)              │  - إصدار بيانات TURN      │
│  - عارض الفيديو         │◄─────────────  P2P  ──────────────────►│    قصيرة الصلاحية         │
│  - مُرسِل أحداث الإدخال    │        (عبر ICE/STUN/TURN)              └───────────┬────────────┘
│  - Ctrl+Alt+9 = فصل     │                                                    │
└────────────────────────┘                                                    │ TURN creds
                                                                              ▼
┌────────────────────────┐                                        ┌────────────────────────┐
│   Host (الكمبيوتر الثاني  │                                        │  TURN/STUN Server        │
│   — المتحكَّم به)         │◄──────────  relay عند الحاجة  ─────────►│  (coturn, REST auth)     │
│                        │                                        └────────────────────────┘
│  - Windows Service      │
│  - WPF UI للإقران فقط    │
│  - التقاط الشاشة + ترميز │
│  - مؤشّر جلسة مرئي (إلزامي)│
│  - مُنفِّذ أحداث الإدخال    │
│  - سجل اتصال محلي         │
└────────────────────────┘
```

### 2.1 الجهاز المتحكَّم به (Host)
- **Windows Service** يعمل في الخلفية ويبدأ مع النظام (بموافقة صريحة عند التثبيت). لا نافذة كبيرة عند كل اتصال.
- **مكوّن جلسة في جلسة المستخدم** (session-in-user-context) لأن التقاط الشاشة وحقن الإدخال يتطلبان جلسة تفاعلية.
- **مؤشّر جلسة مرئي إلزامي**: أيقونة/شارة صغيرة غير قابلة للتعطيل تظهر أثناء وجود اتصال نشط، وتُظهر هوية الجهاز المتصل. هذا شرط تصميمي غير اختياري.
- **واجهة WPF** تُفتح فقط أثناء الإقران الأوّلي ولعرض/إلغاء الأجهزة الموثوقة والسجل.

### 2.2 الجهاز المتحكِّم (Controller)
- **واجهة WPF** لإدخال معرّف الجهاز الهدف، بدء الاتصال، عرض الفيديو، وإظهار زمن الاستجابة وحالة الاتصال.
- **مفتاح فصل شامل Ctrl+Alt+9** يُسجَّل عبر `RegisterHotKey` لإنهاء الجلسة فوراً وتحرير أي مفاتيح/أزرار مضغوطة عن بُعد.

### 2.3 خدمة الإشارات (Signaling)
- ASP.NET Core عبر HTTPS/WSS، تنقل رسائل SDP و ICE candidates بين الطرفين فقط بعد المصادقة.
- لا ترى محتوى الجلسة (الفيديو والإدخال يمرّان P2P عبر WebRTC)، وظيفتها الوساطة والمصادقة وإصدار بيانات TURN.

### 2.4 خادم TURN/STUN
- `coturn` مع مصادقة REST (بيانات اعتماد قصيرة الصلاحية HMAC) لعبور NAT عند فشل الاتصال المباشر.

## 3. تدفّق الإقران (Pairing) — لمرة واحدة

```
Controller                          Signaling                        Host
    │                                   │                              │
    │ 1. يطلب المستخدم إقران Host جديد     │                              │
    │──────────────────────────────────►│                              │
    │                                   │ 2. يُنشئ Host رمز إقران قصير    │
    │                                   │    ويعرضه محلياً على شاشته      │
    │ 3. يُدخل المستخدم الرمز يدوياً        │                              │
    │    (تأكيد فيزيائي على الطرفين)       │                              │
    │──────────────────────────────────►│─────────────────────────────►│
    │ 4. تبادل مفاتيح عامة موقّعة          │                              │
    │◄─────────────────────────────────►│◄────────────────────────────►│
    │ 5. يخزّن كل طرف المفتاح العام للآخر    │                              │
    │    (Controller: مفتاح خاص عبر DPAPI) │  Host يضيف الجهاز لقائمة        │
    │                                   │        الموثوقين + يؤكّد محلياً    │
```

- الرمز قصير الصلاحية، يُعرض على شاشة الـ Host ويجب تأكيده فيزيائياً هناك.
- بعد الإقران، **الوصول اللاحق دون حضور** مشروط بامتلاك المفتاح الخاص المطابق فقط.
- يمكن للمالك عرض الأجهزة الموثوقة وإلغاء أيٍّ منها محلياً في أي وقت.

## 4. تدفّق الاتصال (بعد الإقران)

1. يصادِق الطرفان على خدمة الإشارات (توقيع تحدٍّ challenge بالمفتاح الخاص — إثبات امتلاك المفتاح، لا إرسال المفتاح).
2. تبادل SDP offer/answer و ICE candidates عبر الإشارات.
3. إنشاء اتصال WebRTC مباشر (STUN) أو عبر TURN relay عند الحاجة.
4. قناة فيديو (DTLS-SRTP) من Host إلى Controller؛ قناة بيانات (SCTP) لأحداث الماوس/لوحة المفاتيح من Controller إلى Host.
5. يظهر مؤشّر الجلسة على الـ Host طوال الاتصال.
6. عند الفصل (يدوي، أو Ctrl+Alt+9، أو انقطاع الشبكة): تُحرَّر جميع المفاتيح/الأزرار المضغوطة عن بُعد ويُغلَق المؤشّر.

## 5. مسار الوسائط والأداء

- **الالتقاط**: Windows.Graphics.Capture (Win10 1803+) كخيار أساسي، مع Desktop Duplication (DXGI) كبديل. تقييم أداء كليهما.
- **الترميز**: H.264/H.265 بتسريع عتادي (NVENC / Intel QuickSync / AMD AMF) عند التوفّر، مع بديل برمجي.
- **التكيّف**: ضبط الدقة/الإطارات/البِت-ريت تلقائياً حسب تقديرات النطاق من WebRTC (REMB/Transport-CC).
- **منع تراكم الإطارات**: إسقاط الإطارات القديمة وإعطاء أولوية زمنية لقناة بيانات الإدخال.
- **تعدد الشاشات + DPI**: تعداد الشاشات، تحديد شاشة نشطة، وتحويل الإحداثيات مع مراعاة تحجيم العرض لكل شاشة.

## 6. تدفّق الإدخال

- **الالتقاط على Controller**: أحداث الماوس/لوحة المفاتيح تُطبَّع إلى إحداثيات نسبية + رموز مفاتيح افتراضية.
- **التنفيذ على Host**: عبر `SendInput` (واجهة ويندوز موثّقة) ضمن الجلسة التفاعلية وضمن صلاحيات التطبيق.
- **الأمان**: لا تُنفَّذ الأحداث إلا ضمن جلسة WebRTC مصادَقة وقائمة؛ عند الانقطاع تُرسَل أحداث "رفع" لكل مفتاح/زر معلّق.

## 7. التخزين والأسرار

| العنصر | مكان التخزين | الحماية |
|--------|--------------|---------|
| المفتاح الخاص للجهاز | Windows DPAPI / Credential Manager | تشفير مرتبط بالمستخدم/الجهاز |
| قائمة الأجهزة الموثوقة (مفاتيح عامة) | ملف تهيئة محلي | المفاتيح العامة غير سرّية؛ التحقق بالتوقيع |
| سجل الاتصال | ملف/SQLite محلي | هوية الجهاز + وقت البداية/النهاية + النتيجة، **دون** ضغطات مفاتيح أو محتوى شاشة |
| بيانات TURN | لا تُخزَّن | قصيرة الصلاحية، تُطلب لكل جلسة |

## 8. حدود التصميم الصريحة (Non-Goals)

هذه السلوكيات **خارج نطاق التصميم عمداً** ولن تُنفَّذ:
- الجلسات الخفية أو تعطيل مؤشر الاتصال.
- إخفاء العمليات أو تسميتها بأسماء مضلِّلة.
- تجاوز مضادات الفيروسات أو أنظمة الأمان أو أنظمة مراقبة الامتحانات.
- حقن الشيفرة في العمليات أو أدوات إخفاء النظام (rootkits) أو التثبيت السري أو التشغيل الدائم دون موافقة.
- تجاوز UAC أو التحكم بالشاشات المحمية بوسائل غير مدعومة.
- فتح منافذ تحكم على الإنترنت دون مصادقة.

البديل المشروع لمشكلة حجب مضادات الفيروسات لبرنامج جديد هو **توقيع الكود (code signing)** بشهادة موثوقة وسلوك شفّاف، لا الإخفاء.

## 10. الإصدار المستهدف من .NET والتقنيات

- **.NET 8 LTS** (مدعوم حتى نوفمبر 2026 على الأقل) — سنراجع الترقية إلى أحدث LTS مدعوم عند البناء الفعلي.
- **WPF** لواجهات الإعداد والإقران (Windows-only، مناسب للمتطلّب).
- **WebRTC**: تقييم مكتبة مُصانة بترخيص متوافق (المرشّحون في وثيقة المكتبات ضمن خطة التنفيذ) — القرار النهائي بعد فحص الصيانة والسجل الأمني والترخيص.

## 11. القيود والميزات غير المكتملة (تُحدَّث أثناء التنفيذ)

- اختيار مكتبة WebRTC النهائي معلّق على تقييم الصيانة/الترخيص.
- الترميز العتادي يعتمد على عتاد الجهازين؛ يلزم بديل برمجي.
- لم تُجرَ بعد مراجعة أمنية مستقلة — **لا يوصف التطبيق بأنه جاهز للإنتاج**.
