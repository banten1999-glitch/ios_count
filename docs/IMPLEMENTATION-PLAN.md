# خطة التنفيذ (Implementation Plan)

> تنفيذ تدريجي بمراحل قابلة للاختبار. كل مرحلة تُسلّم شيئاً يعمل ويُختبر قبل الانتقال.
> النطاق: أداة تحكم عن بُعد شفّافة قائمة على الموافقة (راجع `ARCHITECTURE.md` و`THREAT-MODEL.md`).

## المرحلة 0 — الهيكل والأساسات
- إنشاء `RemoteDesktop.sln` والمشاريع في `src/` كما في `ARCHITECTURE.md §9`.
- تهيئة .NET 8، Serilog، xUnit، وإعداد CI أساسي (بناء + اختبارات).
- تعريف نماذج البروتوكول المشتركة في `RemoteDesktop.Core` (رسائل الإشارات، أنواع أحداث الإدخال، بنى الإقران).
- **مخرَج**: حل يُبنى ويمرّ باختبارات فارغة.

## المرحلة 1 — خدمة الإشارات (Signaling) + المصادقة
- ASP.NET Core: نقاط WSS لتبادل SDP/ICE، تسجيل الأجهزة بمفاتيحها العامة.
- مصادقة بإثبات امتلاك المفتاح (توقيع تحدٍّ nonce + طابع زمني) — يعالج انتحال الهوية وReplay.
- تحديد المعدّل وحدود المحاولات.
- إصدار بيانات TURN قصيرة الصلاحية (HMAC).
- **مخرَج**: خدمة إشارات مصادَقة + اختبارات وحدة/تكامل للمصادقة ورفض المحاولات غير المصرّحة.

## المرحلة 2 — الإقران (Pairing) والتخزين الآمن
- توليد زوج مفاتيح لكل جهاز؛ تخزين الخاص عبر DPAPI، والعام في التسجيل.
- تدفّق الإقران: رمز قصير الصلاحية يُعرض على Host ويؤكَّد فيزيائياً؛ تبادل مفاتيح عامة موقّعة.
- قائمة أجهزة موثوقة + واجهة WPF لعرضها وإلغائها محلياً.
- **مخرَج**: إقران يعمل بين جهازين + اختبار قبول/رفض/سحب الثقة.

## المرحلة 3 — قناة WebRTC والإدخال (بدون فيديو بعد)
- إنشاء اتصال WebRTC (SIPSorcery) عبر ICE/STUN/TURN.
- تحقّق بصمات DTLS ضد المفاتيح المقترنة (منع MITM).
- قناة بيانات لأحداث الإدخال: التقاط على Controller → تنفيذ عبر `SendInput` على Host.
- تحرير المفاتيح/الأزرار المعلّقة عند الانقطاع؛ Ctrl+Alt+9 للفصل الفوري.
- **مخرَج**: تحكم بالماوس/لوحة المفاتيح عن بُعد (بلا فيديو) + اختبار الفصل وتحرير الإدخال.

## المرحلة 4 — التقاط الشاشة والفيديو
- التقاط عبر WGC (وبديل DXGI) + ترميز H.264 عبر Media Foundation.
- بثّ الفيديو عبر مسار WebRTC؛ عرض على Controller.
- مؤشّر الجلسة المرئي على Host (إلزامي، غير قابل للتعطيل).
- **مخرَج**: عرض شاشة حي + تحكم متزامن.

## المرحلة 5 — الأداء والتكيّف والاستقرار
- ضبط الدقة/الإطارات/البِت-ريت تلقائياً حسب تقدير النطاق.
- منع تراكم الإطارات وأولوية قناة الإدخال.
- تعدد الشاشات + مراعاة تحجيم DPI.
- حدود إعادة الاتصال وعرض الحالة وزمن الاستجابة المقاس.
- **مخرَج**: أوضاع جودة قابلة للتعديل + قياس زمن استجابة موثّق.

## المرحلة 6 — الخدمة والخلفية والتثبيت
- تشغيل Host كـ Windows Service + مكوّن جلسة تفاعلية.
- حزمة MSI (WiX) بتثبيت شفّاف؛ بدء تلقائي بموافقة صريحة عند الإعداد.
- السجل المحلي (SQLite): هوية + وقت + نتيجة، دون محتوى.
- تعليمات إلغاء الثقة والإزالة الكاملة.
- **مخرَج**: تثبيت/إزالة نظيف + سجل اتصال.

## المرحلة 7 — التوثيق والاختبار الشامل والمراجعة
- تعليمات البناء والإعداد على الجهازين، ونشر الإشارات وTURN، والمنافذ والتكاليف المتكرّرة.
- سيناريوهات الاختبار المطلوبة (الجدول أدناه).
- إعداد لمراجعة أمنية مستقلة (بنود `THREAT-MODEL.md §9`).
- **مخرَج**: توثيق كامل + تقرير اختبار + قائمة قيود صريحة.

## سيناريوهات الاختبار المطلوبة

| # | السيناريو | النتيجة المتوقّعة |
|---|-----------|-------------------|
| 1 | الإقران الأوّلي | نجاح فقط بعد تأكيد فيزيائي على Host |
| 2 | اتصال غير مصرّح (يعرف المعرّف فقط) | **رفض** — لا مفتاح مطابق |
| 3 | إعادة إرسال رسالة مصادقة (Replay) | **رفض** — nonce مستهلك/منتهٍ |
| 4 | فصل محلي (Ctrl+Alt+9) | انقطاع فوري + تحرير كل الإدخال المعلّق |
| 5 | انقطاع الشبكة المفاجئ | تحرير الإدخال + محاولات إعادة اتصال محدودة + حالة واضحة |
| 6 | الاتصال خلف NAT | نجاح عبر STUN أو TURN relay |
| 7 | سلوك مؤشّر الجلسة | يظهر طوال الاتصال ولا يمكن تعطيله |
| 8 | سحب ثقة جهاز | منع اتصاله لاحقاً فوراً |
| 9 | تعدد الشاشات + DPI مختلف | إحداثيات صحيحة على كل شاشة |

## المنافذ والتكاليف المتكرّرة (تُوثَّق تفصيلاً في مرحلة 7)

- **الإشارات**: منفذ HTTPS/WSS (443 مقترح) — استضافة صغيرة (VPS/App Service).
- **STUN**: 3478/UDP. **TURN**: 3478/UDP+TCP و5349/TLS، ونطاق منافذ relay.
- **التكاليف**: استضافة الإشارات (منخفضة)، وخادم TURN (يعتمد على حجم الحركة المُمرَّرة عند الحاجة لـ relay)، وشهادة توقيع كود (سنوية).

## ما هو خارج النطاق (Non-Goals) — يُرفض تنفيذه
راجع `ARCHITECTURE.md §8` و`THREAT-MODEL.md §6`: لا إخفاء/جلسات خفية، لا تعطيل مؤشر، لا تجاوز مضادات فيروسات أو أنظمة امتحانات، لا حقن شيفرة/rootkits، لا تثبيت سري أو persistence دون موافقة، لا تجاوز UAC، لا منافذ بلا مصادقة.
