# قائمة المكتبات والتقنيات (Libraries & Dependencies)

> يُقيَّم كل مكوّن وفق: **الصيانة** (آخر إصدار/نشاط)، **الترخيص** (توافقه مع الاستخدام)،
> **السجل الأمني**، و**الملاءمة** للمتطلّب. القرار النهائي يُثبَّت عند البناء بعد فحص محدّث.

## 1. المنصّة الأساسية

| المكوّن | الخيار | الترخيص | ملاحظة |
|--------|--------|---------|--------|
| Runtime | **.NET 8 (LTS)** | MIT | مدعوم طويل الأمد؛ يُراجَع أحدث LTS مدعوم عند البناء |
| واجهات سطح المكتب | **WPF** | MIT (ضمن .NET) | Windows-only، مناسب للإعداد والإقران |
| خدمة الإشارات | **ASP.NET Core** | MIT | HTTPS/WSS، مصادقة، إصدار بيانات TURN |

## 2. التقاط الشاشة والترميز

| الوظيفة | الخيار الأساسي | البديل | ملاحظات |
|--------|----------------|--------|---------|
| الالتقاط | **Windows.Graphics.Capture** (WinRT) | **Desktop Duplication (DXGI)** | WGC أنظف على Win10 1803+ وأفضل مع تعدد الشاشات؛ DXGI أوسع توافقاً. نقيس الأداء على كليهما |
| الوصول لـ WinRT من .NET | **CsWinRT / Microsoft.Windows.CsWin32** | — | توليد ربط موثّق لواجهات ويندوز |
| الترميز العتادي | **Media Foundation** (H.264/H.265 عبر NVENC/QuickSync/AMF) | ترميز برمجي (OpenH264) | نفضّل مسار العتاد؛ OpenH264 (BSD) كبديل مع مراعاة براءات H.264 |

> **قرار الترميز**: نبدأ بـ H.264 عبر Media Foundation (يستفيد من مُرمِّزات العتاد الموجودة في ويندوز) لتقليل الاعتماديات الخارجية. تقييم H.265/AV1 لاحقاً حسب دعم العتاد على الجهازين.

## 3. WebRTC (النقل الأساسي)

المرشّحون، مع معايير الاختيار:

| المكتبة | اللغة/الربط | الترخيص | الصيانة | ملاحظات الاختيار |
|---------|-------------|---------|---------|------------------|
| **Microsoft MixedReality-WebRTC** | C# رسمي | MIT | ⚠️ **مؤرشف/متوقّف** | ربط C# ممتاز لكنه غير مُصان — **يُستبعد** ما لم يوجد fork مُصان موثوق |
| **libwebrtc (Google) عبر ربط C#** | native + P/Invoke | BSD-3 | نشط (عبر Chromium) | الأكثر نضجاً؛ يتطلّب بناء/ربط native — كلفة تكامل أعلى |
| **SIPSorcery** | C# خالص مُدار | BSD-3 | ✅ **نشط ومُصان** | تنفيذ WebRTC مُدار بالكامل (DTLS-SRTP، ICE، data channels)؛ يبسّط النشر والتوقيع. **المرشّح المبدئي المفضّل** |
| **Pion (Go)** | Go | MIT | نشط جداً | ممتاز لكنه Go؛ يتطلّب عملية/ربط منفصل — يزيد التعقيد |

> **القرار المبدئي**: **SIPSorcery** كمكتبة WebRTC الأساسية لأنها C# مُدارة نشطة الصيانة بترخيص متساهل (BSD-3)، ما يبسّط البناء وتوقيع الكود ويتجنّب اعتماديات native هشّة. نتحقّق من كفاية أدائها للفيديو عالي الدقة؛ إن قصُرت، نرجع إلى libwebrtc عبر ربط native مع توثيق سبب التغيير.

## 4. الإدخال (الماوس ولوحة المفاتيح)

| الوظيفة | الواجهة | ملاحظة |
|--------|---------|--------|
| التقاط الإدخال على Controller | Raw Input / رسائل نوافذ WPF | تطبيع إلى إحداثيات نسبية + Virtual-Key codes |
| تنفيذ الإدخال على Host | **`SendInput`** (Win32، موثّقة) | ضمن الجلسة التفاعلية وصلاحيات التطبيق فقط |
| Hotkey الفصل (Ctrl+Alt+9) | **`RegisterHotKey`** (Win32) | على Controller؛ فصل فوري + تحرير المفاتيح المعلّقة |
| ربط Win32 | **Microsoft.Windows.CsWin32** | توليد P/Invoke موثّق بدل تعريفات يدوية |

## 5. التشفير والتخزين الآمن

| الوظيفة | الخيار | ملاحظة |
|--------|--------|--------|
| تخزين المفتاح الخاص | **DPAPI** (`ProtectedData`) / Credential Manager | مرتبط بالمستخدم؛ لا نص واضح |
| توقيع/تبادل المفاتيح | **libsodium عبر NSec.Cryptography** (MIT) أو `System.Security.Cryptography` (Ed25519/X25519) | نستخدم بدائل قياسية فقط، لا خوارزميات خاصة |
| تشفير النقل | **DTLS-SRTP** (داخل WebRTC) + **TLS 1.3** (الإشارات) | من البروتوكولات نفسها |

## 8. ملخّص قرارات قد تتغيّر (مع الأسباب)

1. **WebRTC**: SIPSorcery مبدئياً (C#/BSD/نشط) → قد ننتقل إلى libwebrtc إن لم يكفِ الأداء (سيُوثَّق السبب).
2. **الترميز**: Media Foundation (عتاد ويندوز) → OpenH264 كبديل برمجي عند غياب دعم العتاد.
3. **الالتقاط**: WGC → DXGI حسب نتائج قياس الأداء والتوافق.
4. **التوقيع/المفاتيح**: نفضّل بدائل .NET المدمجة؛ NSec/libsodium إن لزمت خوارزميات غير مدعومة أصلاً.

> جميع الاختيارات النهائية تخضع لفحص محدّث للصيانة/CVEs/الترخيص لحظة البناء، ولا يُثبَّت أي اعتمادية غير مُصانة أو بترخيص غير متوافق.
