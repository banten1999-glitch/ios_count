## 2. الاختبارات اليدوية على الجهازين (ويندوز)

المطلوب اختباره ميدانياً بعد النشر:

| # | السيناريو | الخطوات | النتيجة المتوقّعة |
|---|-----------|---------|-------------------|
| 1 | الإقران الأوّلي | Pair على الـ Host → إدخال الرمز على الـ Controller → تأكيد محلي | نجاح فقط بعد التأكيد على الـ Host |
| 2 | رفض اتصال غير مصرّح | جرّب Connect من جهاز غير مقترن (يعرف Host ID فقط) | **رفض** — لا مفتاح مطابق |
| 3 | فصل محلي بالمفتاح | أثناء جلسة، اضغط **Ctrl+Alt+9** على الـ Controller | انقطاع فوري + تحرير كل إدخال معلّق على الـ Host |
| 4 | انقطاع الشبكة | افصل شبكة الـ Controller فجأة أثناء جلسة | تحرير الإدخال على الـ Host + المؤشّر يختفي + حالة "disconnected" واضحة |
| 5 | خلف NAT | ضع الجهازين على شبكتين مختلفتين (بدون منفذ مُمرَّر) | نجاح عبر STUN أو TURN relay |
| 6 | مؤشّر الجلسة | راقب الـ Host طوال الجلسة | شارة مرئية دائمة لا يمكن للطرف المتصل تعطيلها |
| 7 | سحب الثقة | Trusted devices → Revoke، ثم جرّب Connect | رفض فوري للاتصال اللاحق |
| 8 | تعدد الشاشات + DPI | جرّب على Host بشاشتين بتحجيم مختلف | إحداثيات الماوس صحيحة على كل شاشة |
| 9 | تكيّف الجودة | قيّد نطاق الشبكة أثناء جلسة | انخفاض الإطارات/الجودة تلقائياً ثم تعافيها |
| 10 | إعادة التشغيل/الوصول دون حضور | أعد تشغيل الـ Host؛ اتصل لاحقاً دون حضور أحد | الاتصال ينجح للجهاز المقترن فقط، مع المؤشّر |

## 3. قياس زمن الاستجابة (Latency)
- الحالة الحالية: تُعرض حالة الاتصال؛ قياس RTT الدقيق عبر إحصاءات WebRTC (`getStats`) **بند مفتوح للمرحلة 5**.
- عند تفعيله، وثّق ظروف الاختبار: نوع الشبكة (LAN/WAN/عبر TURN)، الدقة/الإطارات، وزمن الاستجابة المقاس.

## 4. حدود معروفة تُذكر عند الاختبار
- أثناء ظهور UAC/شاشة الدخول (secure desktop): لا يُلتقط الفيديو ولا يُنفَّذ الإدخال (سلوك موثّق).
- الترميز VP8 مبدئياً؛ H.264 بتسريع عتادي لاحقاً.
- **لا يوصف التطبيق بأنه جاهز للإنتاج قبل مراجعة أمنية مستقلة** (بنود `docs/THREAT-MODEL.md §9`).
